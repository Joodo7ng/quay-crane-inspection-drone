# 통합 코드 설명

## 1. 목적

팀원별로 수집하고 라벨링한 데이터를 같은 기준으로 검사하고, 기존 균열 모델과 부식 모델을 각각 파인튜닝한 뒤 개선 여부를 비교하기 위한 공통 실행 코드임.

수빈의 35장 실험 코드를 기반으로 팀 자료를 받을 수 있도록 확장한 구성임. 균열 모델과 부식 모델은 각각 유지하며, 데이터 처리와 학습 및 평가 절차를 공통화한 상태임. 팀원별 코드에 포함된 모든 실험 기법을 병합한 상태는 아님.

## 2. 입력부터 결과까지

| 순서 | 수행 내용 | 쉬운 설명 |
| --- | --- | --- |
| 1. 데이터 연결 | 사진, Labelme JSON, metadata.csv 읽기 | 사진과 정답, 출처 기록을 서로 연결하는 단계 |
| 2. 입력 검사 | 파일 연결, 라벨 형식, 검수 기록, 원본 그룹과 중복 확인 | 잘못된 자료와 학습 및 평가 자료의 겹침을 찾는 단계 |
| 3. 정답 변환 | 승인된 폴리곤을 픽셀 단위 마스크로 변환 | 모델이 배울 수 있도록 결함 위치를 정답 이미지로 바꾸는 단계 |
| 4. 파인튜닝 | 기존 가중치를 불러와 Train 자료로 추가 학습 | 기존 모델을 팀이 준비한 사진에 맞게 조정하는 단계 |
| 5. Validation 비교 | 동일한 검증 사진에서 학습 전후 성능 비교 | 학습 과정에서 사용할 가중치와 설정을 선택하는 단계 |
| 6. 최종 Test | 모델과 설정을 확정한 뒤 별도 Test로 평가 | 학습과 모델 선택에 사용하지 않은 사진에서 최종 성능을 확인하는 단계 |
| 7. 결과 저장 | 점수표, 사진별 결과, 예측 비교 그림, 실행 설정 저장 | 논문 결과표와 결과 해석에 사용할 근거를 남기는 단계 |

Train, Validation, Test 분할은 팀에서 먼저 확정해 metadata에 기록하는 방식임. 코드가 모든 사진을 임의로 다시 나누는 기능은 아님. 기록되지 않은 유사 사진이나 잘못된 정답 경계는 사람의 확인이 필요한 부분임.

## 3. 두 모델의 학습 방식

균열 모델은 기존 균열 가중치, 부식 모델은 기존 부식 가중치에서 각각 시작하는 구성임. 두 모델 모두 U-Net과 EfficientNet-B0 구조를 사용하는 이진 분할 모델임. 픽셀마다 해당 결함인지 배경인지 예측하는 방식임.

정상 사진은 결함이 없음을 확인한 빈 폴리곤 JSON을 사용함. 균열만 검수한 사진을 부식 모델의 정상 사진으로 자동 사용하지 않으며, 해당 클래스의 라벨 검수가 완료된 사진만 사용함. 부식 등급 라벨은 학습 마스크에서 하나의 corrosion 클래스로 합치고 원본 JSON은 보존함.

기본 설정은 입력 크기 512, 최대 20 epoch, 학습률 0.00003, batch size 2임. 이미지의 기본 특징을 추출하는 인코더를 고정하고 나머지 부분을 추가 학습하는 구성임. 뒤집기, 회전, 밝기 변화, 약한 블러를 적용하며 Validation IoU가 5 epoch 동안 개선되지 않으면 조기 종료함.

실제 사진과 합성 사진을 함께 학습에 사용하는 구성이 가능하나, 어떤 자료를 포함할지는 실험 전에 확정할 사항임. 실제 데이터만 학습하는 조건과 실제 및 합성을 함께 학습하는 조건을 자동으로 모두 실행하는 기능은 아님.

## 4. 결과를 읽는 기준

| 지표 | 확인할 내용 |
| --- | --- |
| IoU와 Dice | 예측 영역과 정답 영역의 일치 정도 |
| Recall | 실제 결함을 얼마나 놓치지 않고 찾았는지 |
| Precision | 결함으로 표시한 영역이 얼마나 정확한지 |
| 정상 오탐 비율 | 정상 사진 중 결함을 잘못 표시한 사진의 비율 |
| 정상 오탐 면적 | 정상 사진에서 잘못 표시한 영역의 비율 |

동일한 평가 사진, 입력 크기, 판정 임계값에서 기존 모델과 파인튜닝 모델을 비교하는 방식임. 실제 사진과 합성 사진은 별도 집계함. 최고 Validation IoU 가중치를 저장하되 Precision, Recall과 정상 오탐까지 검토한 뒤 채택 여부를 판단하는 절차임.

Validation에서 모델과 설정을 확정한 후 Test 실행 가능함. 동일 실행 기록의 반복 Test는 차단하나 파일 복사나 기록 삭제까지 막는 기능은 아니므로 팀의 평가 원칙 준수가 필요한 부분임.

## 5. 파일별 역할 및 현재 상태

| 파일 | 역할 |
| --- | --- |
| import_metadata.py | 팀이 작성한 사진 목록과 검수 정보를 공통 입력 명세로 변환 |
| data.py | 자료 검사와 학습용 및 Test용 입력 준비 |
| labelme_masks.py | Labelme 좌표를 픽셀 정답 마스크로 변환 |
| engine.py | 이미지 처리, 학습 계산과 사진별 예측 |
| run.py | 파인튜닝 실행, 평가 대상 확정, 최종 Test 실행 |
| metrics.py | 평가 지표 계산과 실제 및 합성 결과 집계 |
| 팀통합_균열부식_학습평가0928.ipynb | Colab에서 위 과정을 순서대로 실행하는 노트북 |

공통 코드와 Colab 실행 절차 준비 완료함. 기존 검사와 다섯 조건 비교 검사를 합쳐 소프트웨어 검사 13개 통과함. 이는 임시 자료로 코드 동작을 확인한 결과이며 팀 데이터의 모델 성능 결과는 아님.

팀 전체 데이터 파인튜닝과 최종 Test는 미실행 상태임. 최종 데이터 버전 및 분할 확정, 팀 전체 중복 검사, 부식 기준 가중치 확보 후 실제 학습 진행 필요함. 균열 기준 가중치 호환성은 확인한 상태이며 부식 기준 가중치는 로컬 미확인 상태임.

라벨을 자동 승인하거나 정답 경계를 자동 수정하는 기능, 안벽크레인 구조 인식, 대시보드 연동은 이번 학습 및 평가 코드의 구현 범위에 포함되지 않음.
