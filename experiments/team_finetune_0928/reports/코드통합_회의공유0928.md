# 코드 통합 현황 및 회의 확인 사항

2026-09-28 밤 기준 정리임. 팀 전체 실험 결과가 아닌 공통 실행 코드의 구현 현황임.

## 회의에서 전달할 핵심

팀 데이터를 같은 형식으로 검사하고, 기존 균열 모델과 부식 모델을 각각 파인튜닝한 뒤, 같은 기준으로 학습 전후를 비교하는 공통 코드 준비 완료함. 소프트웨어 검사 11개 통과함. 실제 팀 통합 학습과 최종 Test는 아직 미실행 상태임.

## 통합의 의미

- 수빈의 기존 35장 실험 코드를 기반으로 데이터 검사, 라벨 변환, 학습 및 평가 흐름 공통화함.
- 팀원 사진을 모아 주 결함별 학습 자료로 사용하도록 구성함. 각 사진의 실제 또는 합성 구분 유지함.
- 균열과 부식 모델은 각각 유지함. 기본 구조는 U-Net과 EfficientNet-B0이며 출력은 모델마다 결함 또는 배경의 이진 분할임.
- 팀원 브랜치의 모든 실험 코드를 하나로 병합한 상태는 아님. 개별 실험의 replay, 조각 확대, LOPO 등은 공통 기본 설정에 자동 포함하지 않음.

## 구현한 작업

| 단계 | 구현 내용 | 목적 |
| --- | --- | --- |
| 제출 자료 읽기 | 사진, JSON, metadata.csv 연결 및 담당자 구분 | 파일 혼동 방지 |
| 데이터 검사 | 검수 기록, 파일 해시, 라벨 형식, 이전 학습 사용 이력 검사 | 미검수 및 잘못 연결된 자료 차단 |
| 분할 검사 | 원본 그룹, 출처 URL, 원본 사진, 합성 결함 및 배경의 Train/Validation/Test 교차 검사 | 평가 자료의 학습 유입 방지 |
| 라벨 변환 | Labelme 폴리곤을 픽셀 마스크로 변환 | 균열 및 부식 면적 학습 |
| 부식 라벨 통일 | 기존 부식 세 등급을 이진 corrosion 마스크로 합침 | 공통 부식 탐지 기준 적용 |
| 추가 학습 | 기존 가중치 엄격 로딩, 인코더 고정, 낮은 학습률, 증강 및 조기 종료 | 소량 도메인 데이터 파인튜닝 |
| 비교 평가 | 같은 사진과 임계값으로 기본 모델 및 파인튜닝 모델 비교 | 개선과 오탐 변화를 함께 확인 |
| 결과 저장 | 사진별 지표, 평균 결과표, 정답 및 예측 비교 그림, 설정 및 가중치 해시 기록 | 논문 표와 재현 근거 확보 |

균열만 검수한 사진을 부식이 없는 정상 사진으로 자동 처리하지 않음. 정상 확인된 빈 폴리곤 사진만 두 모델의 공통 정상 자료로 사용 가능함.

## 현재 학습 및 평가 설정

- 입력 크기 512, 최대 20 epoch, 개선 없는 5 epoch에서 종료, 학습률 0.00003, batch size 2를 기본값으로 설정함.
- 인코더 파라미터 및 BatchNorm 상태를 고정함. 나머지 학습 대상만 조정함.
- 뒤집기, 90도 단위 회전, 밝기 변화, 약한 블러 적용함.
- 실제 사진 Validation IoU 기준으로 최고 가중치 저장함. 정밀도, 재현율 및 정상 오탐도 함께 검토한 후 모델 채택 판단 필요함.
- IoU, Dice, Precision, Recall 산출함. 정상은 오탐 발생 사진 비율과 오탐 면적 비율을 별도로 산출함.
- 실제 사진과 합성 사진 결과를 별도로 집계함.
- Validation에서 모델과 기준을 확정한 후 Test 실행하도록 구성함. 같은 실행 기록의 반복 Test는 차단하지만 팀원의 별도 파일 복사까지 막는 보안 기능은 아님.
- 작은 승인 사진은 사진별 예외 기록과 명시적 실행 옵션이 있을 때만 포함하도록 보완함. 입력 리사이즈가 원본에 없는 세부 정보를 복구하는 것은 아님.

## 회의에서 확정할 내용

1. 각자 최종 사용할 ZIP 버전과 라벨 수정 완료 일정 확정 필요함.
2. 균열 및 부식 기준 가중치 파일과 저장 위치 확정 필요함.
3. 공통 실험에서 실제 데이터만 사용할지, 실제와 합성을 함께 사용할지 조건 확정 필요함. 합성 효과를 주장하려면 같은 실제 Test에서 조건별 비교 설계 필요함.
4. 출처 및 장비 사례별 분할, 독립 Test 수량, 실제 정상과 콘크리트 참고 자료 구분 확정 필요함.
5. 기본 실험을 먼저 실행하고 추가 기법의 비교 범위를 제출 일정에 맞춰 결정할 필요가 있음.

작업 우선순위는 최종 데이터 검수 및 분할 확정, 기준 가중치 확보, 공통 파인튜닝, Validation 검토, 최종 Test 및 논문 결과 반영 순서임.
