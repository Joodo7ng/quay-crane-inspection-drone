# 기준 기반 점검 지원 실행 및 기준 관리

## 구현 범위

균열 및 부식의 두 U-Net 모델을 유지하고, 공통 판단 처리부에서 후보 측정값과 점검자가 확인한 부재 및 세부 부위를 연결함. 시스템 우선순위, 외부 참고 지침 및 점검자 최종 판단을 구분함. 외부 법령의 원문 재확인과 현장 안전성 검증을 완료한 제품은 아님.

## 실행

Python 3.11의 macOS CPU 환경에서 검증함. 새 환경 구성 예시임.

```sh
cd /Users/jungsubin/ICT_Drone_Dev
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run dashboard.py --server.address 127.0.0.1
```

검증 과정에서 `.venv`가 준비된 경우 재설치 없이 마지막 명령으로 실행 가능함. Jetson의 Torch 및 CUDA 패키지는 기기 환경에 맞춰 별도로 구성해야 하며 이 macOS 설치 목록을 그대로 강제 설치하지 않음. ONNX를 사용하는 경우 해당 환경에 맞는 onnxruntime 설치가 추가로 필요함. 검증한 모델 형식은 `.pt`임.

균열 기본 경로는 기존 `best_E5_tversky.pt`임. 부식은 사이드바에서 사용 중인 가중치를 명시하거나 `MON_CORROSION` 환경변수로 지정함. 파일명만으로 임의 후보 모델을 선택하지 않음. 이번에 전달받은 ZIP에서 추출한 부식 가중치는 원본과 동일한 검증용 사본임. 가중치를 재학습하거나 교체하지 않음.

장비와 회차를 입력하고 부재 및 부위를 선택한 뒤, 부재 확인 여부와 영상 품질을 표시함. 부재 선택은 해당 관측의 대상이며 한 영상에 여러 부재가 있으면 개별 후보 확인 과정에서 수정해야 함. 사진 여러 장을 한꺼번에 분석할 때 같은 초기 부재 설정이 적용됨.

부재 영역이 필요하면 사진 한 장에 대응하는 동일 해상도의 흑백 PNG를 선택함. 흰색 255가 관측 부재 영역임. 마스크와 사진의 대응 및 부재를 확인해야 사용 가능함. 부재명만 고른 경우에는 부재 기준 면적비를 계산하지 않음. 잘못된 크기, 빈 영역 및 다른 프레임의 마스크는 사용하지 않음.

카메라와 영상 파일 및 화면 캡처 입력을 유지함. 각 분석 프레임과 동일 프레임의 결과를 저장 및 표시함. 영상 파일은 순차 프레임 분석이며 영상 원래 속도로 재생하는 플레이어가 아님. 화면 캡처는 주 모니터를 대상으로 하므로 대시보드 자체가 포함되지 않도록 사용자 배치가 필요함. 카메라 및 화면 녹화 권한은 macOS에서 별도로 허용해야 함.

## 배치 실행

```sh
.venv/bin/python detect_run.py sample_photos \
  --crack best_E5_tversky.pt \
  --corrosion /absolute/path/to/best_corrosion_efficientnet-b0.pt \
  --asset CRANE-01 --inspection INSPECT-01 \
  --component leg --member-id LEG-01 --part 연결부 \
  --confirm-component --quality usable
```

`--component`에는 기준 데이터의 부재 ID를 사용함. 미상은 `unknown`임. `--quality usable`과 `--confirm-component`는 실제 확인 후 지정해야 함. 두 모델 미실행 또는 실패 시 정상으로 기록하지 않음. `--store`로 별도 저장 폴더를 지정할 수 있음. `--threshold` 기본값은 픽셀 이진화 0.5, `--min-area` 기본값은 1픽셀임. 이 수치는 안전 등급 기준이 아님.

과거 100픽셀 미만 제거로 작은 균열 후보가 누락되는 것을 피하도록 기본 최소 영역을 1픽셀로 변경함. 원본 이진 예측과 후처리 마스크를 모두 보존하며 설정값을 기록함. 작은 오탐 후보 수가 늘 수 있음. 이전 100픽셀 제거 조건의 성능 수치와 동일한 운영 조건으로 주장하지 않음.

## 파일 구조

- `model_infer.py`: 기존 두 모델 추론, 모델별 실행 상태 및 가중치 해시를 제공함. 보정된 후보 신뢰도가 없어 신뢰도는 `None`으로 제공함.
- `inspection_pipeline.py`: 업로드, 실시간 및 배치가 공유하는 기준 적용과 저장 진입점임.
- `inspection_rules.py`: 부재 정보 정규화 및 버전이 있는 팀 운영 규칙 평가를 담당함.
- `criteria/inspection_v1.json`: 적용 범위, 조건 연산과 포함 경계, 근거 및 확인 상태를 포함한 기준 데이터임.
- `inspection_store.py`: SQLite 관측 및 추가형 확인·조치 이력, 고유 증거 파일을 관리함.
- `dashboard.py`, `detect_run.py`: 동일 처리부를 호출하는 화면과 배치 진입점임.

## 기준의 의미

현재 활성 규칙은 팀의 후보 확인 순서를 위한 운영 규칙임. 균열 후보는 면적에 관계없이 주의로 두고, 부식 후보는 기본 경미, 확인된 연결부의 부식은 주의로 둠. 이는 법정 기준 또는 구조적 손상 등급이 아니며 현장 전문가 검증을 받았다는 뜻이 아님. FCM 후보 정보만으로 위험 또는 사용 중지를 자동 확정하지 않음. 위험은 점검자가 별도로 판단하고 사유를 남겨 기록 가능함.

외부 기준은 첨부 문서의 조항과 적용 범위를 참고정보로 제공함. 국가법령정보센터 원문은 이 작업의 웹 조회에서 접근되지 않았으므로 `attachment_only` 상태를 유지함. 첨부에서 확인했다고 적힌 내용과 이번 구현에서 독립적으로 검증한 내용을 구분함. 모든 외부 자료는 자동 법정 판단 대상이 아님.

부재 종류가 미상이거나 확인되지 않았으면 특정 부재의 외부 지침을 확정 적용하지 않고 공통 확인 절차를 제공함. 레그의 연결부와 몸통을 구분함. 기계실과 기계 트롤리는 외피와 하중 지지 틀을 같은 FCM으로 단정하지 않도록 세부 부위 확인을 요구함.

균열 길이·깊이, 부식 두께·단면 손실 및 구조 안전성은 산출하지 않음. 면적비는 영상의 후보 마스크 합집합 비율 또는 유효한 부재 관측 영역과의 교집합 비율임. 녹 면적 1%나 기존 0.3/1.5/3/12%를 자동 안전 등급에 사용하지 않음.

기준 수정 시 버전을 올리고 별도 파일로 관리해야 함. 과거 관측에는 당시 기준 전체와 SHA-256을 저장하므로 파일 변경으로 원판단이 바뀌지 않음. 현재 UI의 부재 수정 재적용은 해당 관측의 원래 기준 버전을 사용함. 새 기준으로 일괄 재판정하는 기능은 포함하지 않음. 초안·미검토 또는 외부 지침 분류의 규칙은 자동 우선순위 평가에서 제외함.

## 저장 및 이력

기본 저장 위치는 저장소 안의 `inspection_data/`임. `INSPECTION_STORE` 환경변수로 바꿀 수 있음. 관측 ID별 원본 PNG, 표시 PNG, 원본 업로드 바이트 및 마스크를 저장함. 실시간 입력에서는 원본 프레임 PNG를 저장하며 전체 영상 파일을 자동 복제하지 않음. 파일 해시를 대조해 재조회 시 변조 또는 손상을 감지함.

관측마다 모든 후보를 저장하고 후보 ID를 부여함. 서로 다른 프레임의 동일 결함 추적은 미구현이므로 후보 수와 관측 수를 실제 독립 결함 개수로 해석하지 않음.

점검자는 후보 또는 관측 전체에 대해 결함 확인·오탐 확인·판단 보류, 최종 우선순위 및 최종 판단을 기록할 수 있음. 확인자, 변경 사유와 판단 내용이 필요함. 조치는 예정·진행 중·완료 상태 및 완료 시각을 저장함. 원분석을 덮어쓰지 않고 이력을 추가함. 부재 수정 시 이전 부재 마스크는 자동 재사용하지 않음.

기존 `detections.csv` 및 `status.json`은 변경하지 않음. 기존 CSV는 대시보드에서 읽기 전용으로 조회함. 새 11열 CSV 뒤에 확장 열을 이어 쓰지 않으며 새 기록의 원장은 SQLite와 증거 폴더임. 기존 외부 CSV 소비자는 새 JSON/SQLite로 이전해야 함. `detect(img) -> dict` 형태와 기존 키는 유지하되 `grade`, `overall_grade`, `confidence`의 `None` 및 추가 분석 상태 필드를 처리해야 함.

SQLite는 로컬 단일 운영자 중심의 저장소임. 확인자 이름은 사용자 입력이며 인증된 전자서명이나 변조 방지 감사 시스템은 아님. 데이터의 백업 및 접근권한 관리와 다중 사용자 동시 운영은 후속 과제임.

## 재검증

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q --junitxml=validation/unit_tests.xml
```

`tests/`는 합성 입력과 고정 예측 마스크를 사용한 기능 시험 및 Streamlit 화면 시험임. 실제 두 모델 연결 시험은 `validation/run_dual_integration.py`에 기록돼 있으며 로컬 가중치 경로를 확인한 후 실행함. 검증 결과와 화면은 `validation/` 및 프로젝트의 별도 검증 결과 폴더에 보존함. 기능 성공률을 AI 탐지 정확도나 구조 안전 판정 정확도로 표현하지 않음.
